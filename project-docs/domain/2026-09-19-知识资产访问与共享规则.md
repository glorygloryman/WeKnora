# 知识资产访问与共享规则

## 一句话概括

能不能访问一份知识库，由**两条彼此独立的规则链同时把关**：一条问"你在自己空间里是什么档位"，另一条问"这份资产本身允不允许被你这个空间碰"，两条都过才放行。

## 规则描述

### 第一条链：档位够不够

用户在所属空间内有四档角色，自低到高、高档自动涵盖低档的全部权限：

| 档位 | 能做什么（相对下一档新增的部分） |
|------|------------------------------|
| 访客 | 浏览与搜索空间内的资料、发起问答、管理自己的会话与收藏 |
| 贡献者 | 新建知识库与智能体；对**自己创建的**资产增删改 |
| 管理员 | 对**任何人创建的**资产增删改；管理空间级的模型、存储、外部接入等基础配置 |
| 所有者 | 修改空间本身、管理成员与邀请、管理接口密钥、删除空间 |

平台管理员是**独立于这条阶梯之外**的运维身份，不是"比所有者更高一档"。

### 第二条链：这份资产允不允许你碰

按顺序判定，命中哪条就按哪条授权，且权限依次递减：

1. **是自己空间的资产** → 按第一条链的档位给权限
2. **经共享空间共享而来** → 按共享时设定的档位给权限
3. **经共享的智能体间接可见** → 只给只读

三条都不命中则拒绝。

### 归属规则：贡献者的边界

贡献者能新建资产，但只能改**自己创建的**那些。判定方式是比对资产的创建者与当前操作者；管理员及以上不受此限制。

这条规则带来一个反直觉的结果：**同一个空间里，两位贡献者互相看得见对方的知识库，但都改不了对方的**。

### 共享出去要同时满足两个条件

把一份知识库共享到共享空间，发起人必须**同时**满足：

- 在**资产所在空间**里是该知识库的创建者或管理员及以上
- 在**目标共享空间**里，自己所在的空间持有编辑者及以上档位

两个条件分属两个不同体系，缺一不可。

### 经共享智能体的间接可见是只读且不继承

如果某人没被直接共享某知识库，但别人把一个绑定了该知识库的智能体共享给了他，他能**只读**访问到这份知识库。这个只读是**写死的**：即便共享智能体的人自己对该知识库有编辑权，接收方也不会因此获得编辑权。

### 机器身份不走角色体系

接口密钥是一类独立的调用主体，它的可用范围直接刻在凭证上（可调用哪些能力、可访问哪些知识库），**与任何人的角色无关**。同理，嵌入渠道的网页访客、通讯工具用户也都是独立主体，其可用范围被强制收窄，不继承配置者的权限。

## 适用条件

- 任何一次访问知识库、智能体及其下属内容（资料、分块、问答对、标签、Wiki 页面）的请求
- 任何一次共享或取消共享的操作
- 不适用于：平台级运维操作（走平台管理员身份）、带时效的一次性文件访问凭证（独立机制，与角色和共享都无关）

## 输入与输出

**输入**：调用主体身份（登录用户 / 接口密钥 / 访客等）、目标资产、期望的操作档位（读或写）

**输出**：放行或拒绝。放行时同时产出**本次生效的权限档位**与**生效空间**——后续处理统一按这个结果取数，不再重复判断这份资产究竟属于谁。

## 异常与边界

- **停用成员的既有凭证**：成员状态被置为停用后，其此前签发且尚未到期的登录凭证仍可继续通过校验，直到自然过期或被显式吊销 **（待业务确认：是否应在停用时立即失效）**
- **跨知识库的批量操作**：批量重新解析、批量删除、批量移动这类一次涉及多个知识库的操作，入口只校验档位为贡献者及以上，不在入口处逐个校验知识库归属 **（待业务确认：逐条归属校验是否已在后续环节补齐）**
- **权限总开关关闭时的覆盖面不对称**：系统存在一个关闭空间内权限校验的总开关；关闭后档位与归属校验降级为只记录不拦截，但**跨空间的资产边界校验、平台管理员校验仍然强制生效**。因此"关掉权限校验"不等于"空间内外人人平等"
- **孤儿空间自愈**：若某人访问自己的主空间而该空间已无任何有效成员，系统会自动把他补为所有者。这是为避免空间失去归属，但意味着成员记录异常清空的空间会被下一个访问者接管 **（待业务确认：是否符合预期）**
- 本节前三条来自对现有实现的核查，均为**代码可证的客观现象**，但是否符合产品预期需业务方判断
