# 知识资产组织模型

## 一句话概括

本系统把用户提供的原始资料逐层拆解为**空间 → 知识库 → 知识条目 → 分块**四级，其中只有最底层的分块参与检索与引用，这解释了为什么"资料里明明有这句话却没被检索到"通常不是资料问题而是切分问题。

## 实体与关系

**主干四级**

| 实体 | 业务含义 | 与上下级的关系 |
|------|---------|--------------|
| 空间 | 资产归属与成员边界 | 一个空间含多个知识库 |
| 知识库 | 一批资料的容器，也是检索范围、共享授权与解析策略的配置单元 | 一个知识库含多个知识条目 |
| 知识条目 | 用户视角的一份资料（上传的文档、一个网址、手写内容、导入的问答对） | 一个知识条目拆成多个分块 |
| 分块 | 检索命中的最小单位，也是回答里展示出处时指向的对象 | 叶子层 |

**知识库的三种类型**决定内容形态，建库时选定：

- **文档型**：容纳各类原始资料，按切分策略拆成分块
- **问答对型**：容纳成对的问题与答案，检索时可只索引问题、也可问答一起索引
- **Wiki 型**：不原样保存资料，而是由智能体把资料重新组织成互相链接的条目式知识网

**旁支实体**

- **标签**：知识库内的分类维度，可挂在知识条目上，也可用于问答对的归类
- **Wiki 页面**：Wiki 型知识库的产物，成体系互链，可人工编辑并保留版本
- **Wiki 目录**：Wiki 页面的归类树，可以存在空目录
- **修订记录**：分块与 Wiki 页面被改动前的历史版本，支撑版本对比与回滚
- **临时附件**：用户在对话中临时上传的资料，有有效期，不进入正式知识库

## 字段语义

只列业务含义容易被误解的，完整字段见技术实现参考。

| 字段 | 业务含义 | 必填 | 备注 |
|------|---------|------|------|
| 解析状态 | 一份资料从进入系统到可被检索的进度 | 是 | 取值与流转见下方「映射/转换规则」 |
| 启用状态 | 该资料是否参与检索 | 是 | 停用后资料仍在，只是检索时不出现 |
| 索引状态 | 分块的当前内容是否已同步到检索索引 | 是 | 人工编辑分块后会短暂处于"索引中" |
| 内容修订号 | 分块被人工改动的次数 | 是 | 每次编辑或回滚递增，用于版本对比 |
| 原始内容 | 解析器最初产出的内容，不随人工编辑改变 | 否 | 首次人工编辑时才填入，用于对照"改之前是什么样" |
| 目录路径 | 该资料在知识库内的归类位置 | 否 | 空表示放在根目录；只影响浏览，不影响检索范围 |
| 来源渠道 | 这份资料是从哪个入口进来的（网页、接口、浏览器扩展、各类通讯工具、外部内容平台） | 是 | 用于追溯来源，不影响后续处理 |
| 待处理增强任务数 | 主解析完成后仍在后台跑的增强任务数量 | 是 | 归零后整份资料才真正标记为完成 |
| 内容指纹 | 资料内容的唯一标识 | 是 | 同一知识库内重复上传同一份资料会被识别并拦截 |

## 映射/转换规则

**一份资料从提交到可用，经过四次形态变化：**

1. **原始资料 → 结构化文本**：由解析环节完成，不同格式（文档、表格、演示稿、图片、音频、网页）走各自的解析方式，产出统一的文本与图片引用
2. **结构化文本 → 分块**：按知识库配置的切分策略拆分。切分策略有三档：自动判型、按标题层级切、按版面结构启发式切
3. **分块 → 可检索索引**：为分块建立语义索引与关键词索引，此后才能被检索命中
4. **分块 → 增强产物（可选）**：按知识库配置追加图片描述、语音转写、自动标签、摘要、问题生成、实体关系抽取

**解析状态的业务语义**

| 状态 | 业务含义 | 用户可见表现 |
|------|---------|------------|
| 待处理 | 已收下资料，排队等解析 | 列表里显示等待中 |
| 解析中 | 正在拆解与索引 | 显示进度 |
| 收尾中 | 主体已可检索，增强任务仍在跑 | **此时已可被检索命中**，但摘要等信息可能还没出来 |
| 已完成 | 全部任务结束 | 正常可用 |
| 失败 | 解析未能完成 | 显示失败原因 |
| 已取消 / 删除中 | 用户中途撤销或正在删除 | 从列表移除 |

**"收尾中"是最容易误解的一档**：用户看到的"处理完成"提示对应的可能是这一档，此时资料已能被检索到，但依赖增强任务的信息（如摘要）尚未齐备。

**父子分块**：切分策略可以让一个大段落作为"父块"、其下细分为若干"子块"。检索命中子块，但回答时可回填父块以补足上下文——父块本身不参与检索。

## 完整示例

**场景：法务同事把一份 80 页的合同模板集导入，供全组问答**

1. 该同事在自己所属空间下新建知识库，类型选**文档型**，切分策略用**自动判型**
2. 上传这份 80 页的资料。系统先算内容指纹，确认该知识库内没有重复，再收下资料、记为**待处理**
3. 解析环节把资料拆成结构化文本；因为这份资料有规整的条款标题，自动判型选择了**按标题层级切**，拆出 240 个分块，每个分块大致对应一个条款
4. 系统为 240 个分块建立语义与关键词索引。此时状态转为**收尾中**，资料**已可被检索**
5. 后台继续跑增强任务：为整份资料生成摘要、按知识库已有标签为其打上"合同模板"标签。任务归零后状态转为**已完成**
6. 组里同事提问"违约金上限怎么约定"，检索命中的是第 47 号**分块**（对应违约责任条款），回答里展示的出处也指向这个分块，而不是整份 80 页资料
7. 法务同事发现第 47 号分块因为原文换页被切断了半句，直接在界面上编辑该分块补全。系统保留改动前的原始内容作为对照，修订号加一，并把该分块重新索引

**这个例子说明的两件事**：检索的粒度是分块不是整份资料；分块可以人工修，且修改留痕可回滚。
