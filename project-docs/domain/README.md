# domain/ — 业务领域知识

存放不依赖特定技术栈的业务知识：产品概念模型、业务规则语义、数据流含义、领域术语。

## 划界标准

**换掉技术栈重写系统，这条知识还有用 → 放 domain/**
**换了技术栈就作废 → 放 decisions/、learnings/、archive/，或当前迭代的 iterations/<迭代>/二次设计.md**

## 命名规则

`YYYY-MM-DD-中文主题.md`

全局业务文档固定命名 `<首次写入日期>-全局业务文档.md`，全工程唯一一份，由 `save-domain` 第六档维护。

## 文档模板

模板一律以 `save-domain` 为准，本页模板仅为示意。

> 术语类文档改用 `save-domain` 的术语表模板 D1（必含「一句话概括 / 术语定义 / 技术实现参考」三段），并在 frontmatter 带 `type: 领域术语`。下方通用模板不适用于术语表。

```
---
tags: [关键词1, 关键词2]
scope: [相关业务模块/领域]
updated: YYYY-MM-DD
---

# 标题

## 业务背景
[这个领域概念解决什么业务问题]

## 核心模型
[概念模型、实体关系、业务规则]

## 边界与约束
[业务层面的限制条件，不涉及具体技术实现]
```

## 典型内容

- 领域实体关系模型（如"轨迹数据的星型拓扑：Person + Event + Location"）
- 业务规则语义（如"风险评估采用纯计算层设计，不产生副作用"）
- 数据流含义（如"数据血缘追踪：source → transform → sink"）
- 领域术语定义（如"标签、策略、规则、评估"在本系统中的精确含义）
