## 1. 项目定位（推断）

> 引用 README：
> "**WeKnora** is an open-source, LLM-powered knowledge framework built for enterprise-grade document understanding, semantic retrieval, and autonomous reasoning."

> 引用 README：
> "It is organized around three core capabilities: **RAG-based Quick Q&A** for everyday lookups, a **ReAct Agent** that autonomously orchestrates retrieval, MCP tools, a **tenant skill catalog**, session-persistent **Docker / E2B / Cube sandboxes** and web search to handle complex multi-step tasks, and a brand-new **Wiki Mode** in which agents distill raw documents into a self-maintaining, interlinked markdown knowledge base..."

由此可推断 WeKnora 定位为一套可自托管的企业知识库框架：把非结构化文档转化为可检索、可问答、可自动整理成 Wiki 的知识资产，并叠加智能体（Agent）自主编排检索/工具/沙箱的能力。README 同时强调"完全模块化、可自托管、数据主权"，暗示目标客群包含对数据隐私敏感的私有化部署场景 **（待确认：目标客群、商业化模式、优先市场——源代码未体现，需业务补充）**。

## 3. 能力清单（推断）

### 3.1 租户、认证与权限

- **多方式登录认证** — 支持账号密码、JWT、OIDC 单点登录
  依据：`internal/router/routes_auth_tenant.go`（`/auth/login`、`/auth/oidc/start`、`/auth/oidc/callback`、`/auth/register`、`/auth/register-by-invite`）
- **空间（租户）内四级角色矩阵** — Owner/Admin/Contributor/Viewer 按角色递增继承权限，且区分"归属守卫"（自己创建的资源）与"角色守卫"（空间级基础设施）
  依据：`internal/router/rbac.go`、`docs/RBAC说明.md`
- **跨空间共享空间（Organization）协作** — 空间可加入共享空间以共享知识库/智能体给其他空间成员使用
  依据：`internal/router/routes_agent.go`（`/organizations`、`/join`、`/invite-code`、`/join-requests`）、`docs/共享空间说明.md`
- **能力位分级的 API Key（Principal 模型）** — 支持空间级/平台级 API Key，按能力粒度授权并可限定知识库范围
  依据：`internal/router/routes_auth_tenant.go`（`/api-keys`、`/api-principal-config`）、`internal/middleware/api_key_gate.go`
- **系统管理员与跨租户运营** — 独立于空间 Owner 的系统级管理员身份，管理全局设置、任务队列、平台 Key、跨空间审计
  依据：`internal/router/routes_auth_tenant.go`（`/system/admin`、`/tenants/all`）、`website-docs/03-features/20-platform-admin.md`

### 3.2 知识库与文档管理

- **多类型知识库（FAQ / 文档 / Wiki）与目录树** — 支持按原始上传目录结构浏览、重命名、移动文档
  依据：`internal/router/routes_knowledge.go`（`/folder`、`/folders/:folder_id`、`/move`）
- **分块（Chunk）编辑与版本回溯** — 检索片段可在 UI 中编辑，带版本快照、diff、一键回滚，编辑后自动重新索引
  依据：`internal/router/routes_knowledge.go`（`/:knowledge_id/:id/revisions`、`/:knowledge_id/:id/revert`）
- **批量操作** — 批量重解析、批量删除、批量下载、知识库复制
  依据：`internal/router/routes_knowledge.go`（`/batch-reparse`、`/batch-delete`、`/batch-download`、`/copy`）、`internal/types/task.go`（`TypeKnowledgeListReparse`、`TypeKBClone`）
- **文档自动打标签** — 解析后从知识库既有标签集中挑选匹配标签，不新建标签、不覆盖人工标签
  依据：`internal/application/service/knowledge_auto_tag.go`、`internal/types/task.go`（`TypeKnowledgeAutoTag`）
- **FAQ 管理** — FAQ 条目导入导出、相似问题、批量维护
  依据：`internal/router/routes_knowledge.go`（`/entries`、`/faq/import/progress/:task_id`）、`internal/application/service/knowledge_faq_import.go`
- **每次上传的解析配置覆盖** — 上传或重解析时可覆盖解析器、分块策略、多模态、图谱抽取、问题生成等参数
  依据：`internal/application/service/knowledge_process_config.go`、`internal/router/routes_knowledge.go`（`/chunker/preview`）

### 3.3 文档解析与知识增强

- **独立文档解析服务** — 文档解析从 Go 主服务剥离为 Python gRPC 服务 `docreader`，支持 PDF/Word/Excel/PPT/图片/CSV/EPUB/MHTML/XMind 等 10+ 格式
  依据：`docreader/pyproject.toml`、`website-docs/03-features/03-document-parsing.md`
- **自适应三档分块策略** — `auto` 自动判型，按 `heading`（Markdown 标题）/`heuristic`（PDF 结构启发式）分级回退
  依据：`docs/CHUNKING.md`
- **多模态增强** — 图片 OCR + VLM 生成描述、音频 ASR 转写
  依据：`internal/models/vlm`、`internal/models/asr`、`internal/types/task.go`（`TypeImageMultimodal`）
- **知识图谱抽取与关系检索** — 入库时抽取实体关系（依赖 Neo4j），问答时沿关系检索补充上下文
  依据：`website-docs/03-features/09-knowledge-graph.md`、`internal/types/task.go`（`TypeChunkExtract`）、`config/config.yaml`（`extract.extract_graph`）

### 3.4 检索与问答

- **事件驱动的 RAG 问答流水线** — 改写→意图识别→并行检索→重排→网页抓取→融合合并→截断→上下文组装→流式生成，各阶段为可插拔 Plugin
  依据：`website-docs/02-architecture/04-rag-pipeline.md`、`internal/application/service/chat_pipeline/chat_pipeline.go`
- **多引擎混合检索** — 同一套检索抽象支持 Postgres(pgvector)/Elasticsearch/OpenSearch/Milvus/Weaviate/Qdrant/Doris/腾讯 VectorDB，知识库可跨引擎检索扇出
  依据：`internal/container/engine_factory.go`、`internal/application/service/knowledgebase_search_fanout.go`
- **SSE 流式问答与断线续传** — 生成过程经 EventBus→StreamManager（内存/Redis）以 SSE 推送，可停止/续传
  依据：`internal/router/routes_chat.go`（`/continue-stream/:session_id`、`/:session_id/stop`）、`internal/stream/redis_manager.go`
- **追问与建议问题** — 基于知识库内容自动生成建议问题、答后追问
  依据：`internal/router/routes_chat.go`（`/messages/:message_id/suggestions`）、`internal/types/task.go`（`TypeQuestionGeneration`）
- **检索效果评测** — 全流程可视化评测，含召回命中率、BLEU/ROUGE 指标
  依据：`internal/router/routes_infra.go`（`/evaluation`）**（待确认：评测的验收阈值/基线数据集来源，源代码未体现）**

### 3.5 智能体（Agent）与工具调用

- **ReAct 多步推理智能体** — 自主编排检索、MCP 工具、技能沙箱、Web 搜索完成复杂任务
  依据：`internal/agent/engine.go`、`internal/router/routes_agent.go`（`/agent-chat/:session_id`）
- **内置与自定义智能体目录，支持共享/停用** — 智能体可在共享空间内共享给其他空间使用
  依据：`config/builtin_agents.yaml`（`builtin-quick-answer`/`builtin-smart-reasoning`/`builtin-data-analyst`/`builtin-wiki-researcher`/`builtin-wiki-fixer`/`builtin-skill-installer`）、`internal/application/service/agent_share.go`
- **MCP 工具集成（含 OAuth）** — 接入外部 MCP 服务，支持会话中动态 OAuth 授权
  依据：`internal/mcp/oauth_lifecycle.go`、`internal/router/routes_infra.go`（`/mcp-oauth/callback`）
- **技能沙箱运行时（Docker / E2B / Cube）** — 会话级持久沙箱执行 Shell、文件操作、数据分析等工具，按租户配置网络策略
  依据：`internal/sandbox/config_sandboxes.go`、`internal/agent/tools/shell_exec.go`、`website-docs/03-features/22-skills-sandbox.md`
- **浏览器技能（browserskill）** — 基于 chromedp 的网页浏览/操作能力，供 Agent 调用
  依据：`internal/browserskill/manager.go`、`internal/agent/tools/browserskill.go`

### 3.6 Wiki 模式

- **文档自动蒸馏为互联 Wiki** — Agent 将原始文档整理为结构化、互相链接的 Markdown Wiki 页面
  依据：`internal/application/service/wiki_ingest.go`、`internal/types/task.go`（`TypeWikiIngest`、`TypeWikiFinalize`）
- **Wiki 页面版本历史与回滚** — 快照 + 行级 diff + 一键回滚 + 人工在线编辑
  依据：`internal/agent/tools/wiki_write_page.go`、`wiki_page_revisions` 表
- **Wiki 独立任务隔离与问答加权** — Wiki 生成使用独立 worker pool，问答重排阶段对 Wiki 内容加权（`PluginWikiBoost`）
  依据：`website-docs/02-architecture/05-async-tasks.md`、`website-docs/02-architecture/04-rag-pipeline.md`

### 3.7 跨会话长期记忆

- **画像/偏好/事实/任务/兴趣五类记忆的后台抽取** — 按调用者身份（空间+IM 用户/嵌入访客等）隔离，自动抽取后需人工确认
  依据：`internal/router/routes_memory.go`（`/items/:id/confirm`、`/items/:id/reject`）、`website-docs/03-features/23-memory.md`
- **记忆主题归纳与晋升** — 相关记忆聚合为主题，可晋升为更稳定的长期条目
  依据：`internal/router/routes_memory.go`（`/topics/:id/promote`）
- **对话内按需检索记忆** — Agent 工具 `search_memory` 在推理中主动查询长期记忆
  依据：`internal/agent/tools/search_memory.go`

### 3.8 数据源导入（外部知识同步）

- **多平台内容持续同步** — 飞书 Wiki/飞书云文档、GitLab、腾讯 IMA、Notion、语雀、RSS、Confluence、钉钉文档等接入知识库

- **定时增量/全量同步调度** — 首次全量、后续按连接器能力增量更新
  依据：`internal/datasource/scheduler.go`、`internal/types/task.go`（`TypeDataSourceSync`）、`website-docs/03-features/10-datasource.md`

### 3.9 IM 集成与对外发布

- **多 IM 渠道机器人问答** — 企业微信/飞书/Lark/QQ 机器人/Slack/Telegram/钉钉/Mattermost/微信/云之家

## 5. 数据流概览（推断）

**文档知识入库主链路**：

用户/数据源上传文件或 URL → `internal/router` 接收并鉴权（RBAC + 归属校验）→ 入队 `document:process` 任务（asynq / Lite 同步执行器）→ 调用独立 `docreader` gRPC 服务解析为文本+图片引用 → 按自适应三档策略分块（`auto`/`heading`/`heuristic`）→ 视配置扇出富化子任务：多模态（VLM/ASR）、知识图谱实体关系抽取（需 Neo4j）、自动标签、摘要/知识库画像、问题生成 → 向量化并写入所配置的检索引擎（Postgres/ES/OpenSearch/Milvus/Weaviate/Qdrant/Doris/腾讯 VectorDB 之一或多个）→ 知识库画像/Wiki 生成任务可在后处理完成后触发（`kb:profile`、`wiki:ingest`）。

**问答主链路**：

用户在 Web/IM/嵌入挂件发起提问 → `internal/router` 鉴权（含嵌入渠道专属鉴权，会丢弃请求方指定的知识库/模型覆盖 **（待确认：嵌入渠道的具体降级规则边界，需业务方最终确认）**）→ 进入事件驱动 Pipeline（`internal/application/service/chat_pipeline`）：加载历史 → 查询改写/意图识别/实体抽取 → 并行检索（向量+关键词+FAQ+知识图谱关系检索）→ 重排（含 Wiki 加权）→ 网页抓取（如启用 Web 搜索）→ 结果融合 → 截断 Top-K → 组装上下文 → 调用 LLM 流式生成 → 经 EventBus/StreamManager 以 SSE 推送给客户端，支持断线续传与手动停止。

**Agent（ReAct）链路**：

用户提问/下达任务 → `internal/agent` 引擎多轮循环：判断是否调用工具（知识检索、MCP 工具、技能沙箱 Shell/文件/DuckDB 分析、Web 搜索、长期记忆查询）→ 汇总工具结果 → 继续推理或生成最终答案，全程可选接入 Langfuse 追踪 **（待确认：ReAct 循环的最大步数、失败重试与超时策略等具体业务口径，需业务方核对代码常量与实际运营参数是否一致）**。

**Wiki 生成链路**：

知识库内容后处理完成 → 触发 `wiki:ingest` 任务（独立 worker pool，硬隔离）→ Agent 将文档蒸馏、去重、归类为互联 Wiki 页面并建立引用/链接 → 支持人工在线编辑、版本快照与一键回滚 → `wiki:finalize` 做知识库级收尾（索引重建、死链清理、交叉链接）。

**数据源同步链路**：

管理员在知识库内配置数据源连接（飞书/Notion/GitLab/语雀/腾讯 IMA/RSS/Confluence/钉钉等）→ 调度器按计划触发 `datasource:sync` 任务 → 首次全量拉取，后续按连接器能力增量更新 → 增量内容复用文档入库主链路完成解析与索引 **（待确认：各连接器"来源删除后如何处理"的具体策略是否一致，源码按连接器可能各异，需业务方逐一核对）**。
